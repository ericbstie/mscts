# How vanilla turns player versus player damage off — 2026-10-15

Evidence for #53 (`combat/pvp-off`). Facts are **verified** with `scripts/research/javap.py` on the
26.3 server jar.

## It is a game rule

- `GameRules.<clinit>` registers `pvp` with `registerBoolean`, category `PLAYER`, default `true`
  (`GameRules.PVP`).
- `DedicatedServerProperties` has no `pvp` string, so `server.properties` has no such key in 26.3.
  Nothing in `ServerSpec` is needed: a Group turns it off with `gamerule pvp false` and back on
  with `gamerule pvp true`.
- `ServerLevel.isPvpAllowed` reads `GameRules.PVP` from the level's rules.

## What it stops

- `ServerPlayer.canHarmPlayer(Player)` is `isPvpAllowed() && Player.canHarmPlayer(Player)`.
- `ServerPlayer.hurtServer` returns `false` before it does any damage when the source's entity is
  a `Player` that `canHarmPlayer` refuses. So a hit by a player does no damage to the victim; what
  else the server sends about the hit is left to the live comparison.
