# Pumpkin research — 2026-09-26

Facts about the Pumpkin nightly, found while building `PumpkinAdapter`.
**Verified** means observed first-hand in this container; **source** means
read in Pumpkin's source at the commit the `nightly` tag pointed to,
`003d3c49` (2026-09-26, "fix(block): notify clients when blocks break on
their own (#3722)"), cloned from `https://github.com/Pumpkin-MC/pumpkin`.
Candidate source explains a Candidate; it never decides what is correct.

## Provision

- `https://github.com/Pumpkin-MC/Pumpkin/releases/download/nightly/pumpkin-X64-Linux`
  answers `302` to a signed, short-lived (about 1 h) URL on
  `release-assets.githubusercontent.com`, which serves the binary as
  `application/octet-stream`: 126,666,792 bytes, `Last-Modified` 2026-09-25
  23:41 UTC. **verified** (curl, headers only)
- The nightly publishes no hash, so `PumpkinAdapter.provision` records the
  sha256, size, final URL and fetch time in `SOURCE.json` and checks the
  cached binary against it on every later provision. It never refreshes a
  cached nightly by itself: delete the Installation to get today's.
- **This container cannot fetch it with Python.** The agent proxy
  re-terminates TLS for `github.com` and `release-assets.githubusercontent.com`
  with its own CA (`CN = CCR Upstream Proxy CA (staging)`), which has no
  keyUsage extension. Python 3.13's `ssl.create_default_context()` sets
  `VERIFY_X509_STRICT`, which rejects such a CA:
  `CERTIFICATE_VERIFY_FAILED: CA cert does not include key usage extension`.
  Mojang's hosts are passed through with their real chain, so
  `VanillaAdapter` is unaffected. **verified**

The live runs below used the session-1 binary (`0.2.0+26.3-26.51 (Commit:
a4d6465)`, sha256 `88b1f5f3…`). Between `a4d6465` and `003d3c49` (two
commits), nothing changed in `pumpkin-config`, `pumpkin/src/data`, the Java
login code, `world_info`, `lib.rs`, `main.rs`, `server/mod.rs` or
`telemetry.rs`.

## Running it

- It takes no arguments and ignores any it is given. It reads
  `pumpkin.toml` and `data/*.json` from its cwd and writes `world/`,
  `logs/latest.log`, `plugins/` and `data/*.json` there. **source, verified**
- A first run in an empty directory writes the complete default
  `pumpkin.toml` (239 lines, random `seed`) and `data/banned-ips.json`,
  `banned-players.json`, `ops.json` and `whitelist.json`, each `[]`. That
  file is `src/mscts/adapters/data/pumpkin.toml`. It was run inside
  `unshare -n`, because the pristine config binds `0.0.0.0:25565` and phones
  home. **verified**
- With the pristine config it exits with code 1 about 1 s after starting,
  because the Bedrock UDP bind fails in this container ("Address family not
  supported by protocol (os error 97)"). The files are written before that.
  **verified**
- The only environment variables it reads are `RUST_LOG` (the log filter)
  and, through reqwest, the proxy variables. It runs with an empty
  environment. **source, verified**
- `commands.use_console = true` reads console lines from stdin. With stdin
  not a TTY, it logs "The input is not a TTY; falling back to simple
  logger" and reads lines. The console starts before the listener answers
  a status ping. **source, verified**

## pumpkin.toml — source, verified

- On load Pumpkin merges the file over its defaults. A key it misses gets
  its default and the file is **rewritten** ("pumpkin.toml changed because
  values were missing"). A key it does not know is kept and ignored.
- **If the merged table does not deserialize (one value of the wrong type
  or out of range: a `u32` gets -1, a `NonZero<u8>` gets 0 or 300, a
  malformed `SocketAddr`), it silently uses its whole default config**
  (`try_into().unwrap_or_else(|_| Self::default())`): online mode,
  encryption, telemetry and Bedrock on, `0.0.0.0:25565`. A TOML syntax
  error does the same, with only an error log line. So `PumpkinAdapter`
  refuses any ServerSpec value that does not fit Pumpkin's type.
- It then asserts `view_distance` is in 2..=64, that encryption is on if
  online mode is, and that `allow_chat_reports` implies online mode. A
  failed assert is a panic at startup.
- The file `PumpkinAdapter` writes for `ServerSpec(port=…)` was **not
  rewritten** by Pumpkin, so it holds every key Pumpkin knows.
- `default_difficulty` is **never read** (grep: defined and defaulted,
  used nowhere). A new world is always `normal` (`LevelData::default`).
  With `default_difficulty = "Peaceful"`, the console `difficulty` said
  "The difficulty is Normal", and `level.dat` has `difficulty: "normal"`.
- `use_favicon = false` logs "Favicon usage is disabled." and the status
  response has `"favicon": null`. `plugins.enabled = false` logs "Plugin
  system is disabled in configuration."
- Status response for `ServerSpec(port=…)`:
  `{"version": {"name": "26.3", "protocol": 777}, "players": {"max": 20, "online": 0, "sample": []}, "description": {"text": "mscts"}, "favicon": null, "enforceSecureChat": true}`.
  Vanilla sends `{"description": "mscts", "players": {"max": 20, "online": 0}, "version": {"name": "26.3", "protocol": 777}}`.
  So Pumpkin adds `players.sample`, `favicon: null` and
  `enforceSecureChat: true` (with `allow_chat_reports = false`), and
  `description` is an object. The Comparison must surface or canonicalize
  these; the Adapter cannot change them.

## Operators — source, verified

- **Pumpkin's offline UUID is not vanilla's.** It is the first 16 bytes of
  the SHA-256 of the bare name, with no version bits
  (`Uuid::from_slice(&Sha256::digest(username)[..16])`). Vanilla's is the
  MD5, version 3 UUID of `OfflinePlayer:<name>`. `Notch` is
  `ff4af744-2839-cc96-4605-0dd2214a30c1` on Pumpkin and
  `b50ad385-829d-3141-a216-7e7d7539ba7f` on vanilla. The player gets this
  UUID at login, so it also shows in `login_finished` and player info.
- An operator is matched to a player by UUID, so `data/ops.json` must carry
  Pumpkin's UUID: an entry with the vanilla UUID ops nobody.
- The console `op Notch` then `op mscts_op` wrote `data/ops.json` as
  serde_json pretty-prints it: 2-space indent, no final newline, keys
  `uuid`, `name`, `level` (from `op_permission_level`, 4) and
  `bypasses_player_limit` (snake_case; vanilla's `bypassesPlayerLimit`
  would fail to parse, and Pumpkin would load no operators). That is
  byte for byte `json.dumps(entries, indent=2, ensure_ascii=False)`.
  Offline, `op` needs no lookup and keeps the name's case.
