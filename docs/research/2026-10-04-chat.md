# How vanilla passes chat on, and when it kicks for it — 2026-10-04

Evidence for #65, the chat Groups. Facts are **verified** with `scripts/research/javap.py`
on the 26.3 server and client jars unless a line says *live* (two vanilla 26.3 Instances,
2026-10-04) or *inferred*. Packet layouts follow wiki.vg revision 3790659 and agree with
javap.

## What the client sends

- `ServerboundChatPacket`: the message (`writeUtf` with a limit of 256), an `Instant` as a
  Long of epoch milliseconds, a Long salt, an optional 256-byte `MessageSignature`, and
  `LastSeenMessages$Update`: a VarInt offset, a fixed bit set of 20 (3 bytes) and a Byte
  checksum.
- `ClientPacketListener.sendChat` takes `Instant.now()`, a salt from
  `Crypt$SaltSupplier.getLong`, and the last-seen update. With no chat session (offline
  mode, no keys) `signedMessageEncoder.pack` gives null, so the signature is empty.
- `LastSeenMessages.computeChecksum` starts at 1 and folds in each signature; for an empty
  list it is 1. The server ignores a checksum of 0 (`Update.verifyChecksum`).
- `sendCommand` parses the command; `SignableCommand.of` lists its message arguments. With
  none it sends `chat_command`; with any it sends `chat_command_signed`, with the time, a
  salt, one signature per argument (none without a session) and the last-seen update. So
  `/me`, `/say`, `/msg` and `/teammsg` go signed, and `/tellraw` does not.

## What the server does with a message

- `handleChat` checks the last-seen update first (a failure disconnects with
  `chat_validation_failed`), then `tryHandleChat`:
  - `isChatMessageIllegal`: a character that is `§` (167), below 32, or 127 disconnects
    with `multiplayer.disconnect.illegal_characters`, on the network thread.
  - Chat hidden in the client's options: a red `chat.disabled.options` system_chat.
  - Otherwise the message is handled on the server thread.
- A message of more than 256 characters fails to decode: the reason is
  `disconnect.genericReason` with "Internal Exception:
  io.netty.handler.codec.DecoderException: Failed to decode packet
  'serverbound/minecraft:chat'" (*live*).
- With no chat session the message is `PlayerChatMessage.unsigned`, whose
  `SignedMessageBody.unsigned` takes `Instant.now()` (the server's clock) and salt 0.
  So `player_chat.timestamp` differs between two servers, and the salt never does: the
  timestamp is in `compare.RANDOM_FIELDS`, and nothing else needs one.
- `broadcastChatMessage` sends `player_chat` to every player, the sender included, with
  `chat_type` reference 0 (`minecraft:chat`), `index` 0 and a `global_index` counted per
  receiver (*live*).

## Commands

- `performUnsignedChatCommand` refuses an unsigned command with a message argument only
  when the server enforces secure profiles; the Adapter sets
  `enforce-secure-profile=false`.
- Sent unsigned (*live*): `/me` gives `disguised_chat` with chat type 1, `/say` type 4 and
  `/msg` type 3 with a `target_name`.
- Sent signed with no signatures (as the client sends them), `collectUnsignedArguments`
  makes each argument `PlayerChatMessage.unsigned`, and each command sends `player_chat`
  instead.
- `/tellraw @a` sends `system_chat` (*live*).
- `team join <team> <a> <b>` fails: the members argument takes one score holder there
  (*live*). Join each player with its own command.

## Spam

- `detectRateSpam` adds 20 to `chatSpamThrottler` for each message. When the count reaches
  the threshold, a player who is not an operator (and not a singleplayer owner) is
  disconnected with `disconnect.spam`.
- The throttler is `TickThrottler(20, 20 * chat-spam-threshold-seconds)`: (20, 200) with
  the Adapter's 10.
- `TickThrottler.tick` takes 1 off a count above 0. `ServerGamePacketListenerImpl.tick`
  calls it on every server tick, and the world being frozen does not stop that
  (2026-10-03-tick-step.md: connections tick when frozen). So `/tick freeze` cannot hold
  the count, and the kick point is the number of messages that arrive within a tick: 10.
- *Live*: 10 messages sent at once right after a barrier were all broadcast, then the
  player was kicked, on both Instances. An operator sending the same is not kicked.

## Joins and leaves

- *Live*: when a player joins, the others get `system_chat`
  `multiplayer.player.joined` (yellow), then `player_info_update`. When it leaves they
  get `system_chat` `multiplayer.player.left`, then `player_info_remove`.
