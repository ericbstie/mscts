# The day cycle: `set_time`, time commands and sleep (26.3)

Sources, for #63: javap of the 26.3 server jar (`scripts/research/javap.py server -v`), the
jar's `data/minecraft/timeline/day.json`, minecraft.wiki `Java_Edition_protocol/Packets`
revision 3799543 ("Update Time"), and live plays against vanilla 26.3 and Pumpkin nightly.

## `set_time` layout

`ClientboundSetTimePacket.STREAM_CODEC` is a Long game time, then
`ByteBufCodecs.map(HashMap::new, WorldClock.STREAM_CODEC, ClockNetworkState.STREAM_CODEC)`:

| Field | Type | Notes |
| --- | --- | --- |
| game time | Long | ticks since the world was made; no command changes it |
| clock count | VarInt | |
| clock | VarInt | a `minecraft:world_clock` registry id: 0 `overworld`, 1 `the_end` |
| total ticks | VarLong | the clock's time |
| partial tick | Float | the fraction of a tick |
| rate | Float | clock ticks per tick; 0 while paused or with `advance_time` false |

The wiki agrees. Recorded payloads (after the packet id 0x73):

- the heartbeat, `000000000000002700`: game time 39, no clock;
- `time set 1000`, `00000000000000300100e807000000003f800000`: the overworld clock alone;
- the join, `000000000000001e02001e000000003f800000011e000000003f800000`: both clocks.

Pumpkin's `set_time` decodes with the same layout. Its join sends only the overworld clock.

## When `set_time` is sent

- `MinecraftServer.tickChildren` runs, in order: the players, the functions, then
  `clockManager.tick()` only if `tickRateManager.runsNormally()`, then
  `forceGameTimeSynchronization()` if `tickCount % 20 == 0`, then each level's tick. The
  heartbeat is stamped with the game time from before the level tick adds one, and it is sent
  whether the world is frozen or not.
- `forceGameTimeSynchronization` sends `new ClientboundSetTimePacket(gameTime, Map.of())`: no
  clock.
- `ServerClockManager.tick` moves each clock only when the `advance_time` game rule is true. It
  sends nothing.
- `ServerClockManager.modifyClock` (`time set`, `time add`, a time marker, pause, rate) changes
  the clock and broadcasts a `set_time` with that one clock at once, inside the command.
- `gamerule advance_time` broadcasts a full sync of every clock, rate 0 when false and 1 when
  true (live).

## Time commands

`TimeCommand` in 26.3 has `time set <time>|<marker>`, `time add <time>`, `time pause`,
`time resume`, `time rate`, and `time query time|gametime|<timeline> [repetition]`, each also
under `time of <clock>`. Queries answer the sender only; `set` and `add` also go to the other
operators as admin chat.

The `day` timeline (`day.json`) has period 24000 and the markers `day` 1000, `noon` 6000,
`night` 13000, `midnight` 18000 (shown in commands), `roll_village_siege` 18000 and
`wake_up_from_sleep` 0.

Live on vanilla, from 0:

| Command | Answer |
| --- | --- |
| `time set 1000` | `commands.time.set.absolute` 1000 |
| `time set day` at 1000 | `commands.time.set.already_at_time_marker` (an error) |
| `time set noon`, `night`, `midnight` | 6000, 13000, 18000 |
| `time add 100`, then `time add 24000` | 18100, then 42100 |
| `time query day` | `commands.time.query.timeline` (`minecraft:day`, 18100: the ticks into the day) |
| `time query day repetition` | `commands.time.query.timeline.repetitions` (1: the day count) |
| `time query time` | `commands.time.query.absolute` (`minecraft:overworld`, the total ticks) |
| `time query gametime` | the game time, which differs between Instances |
| `time query daytime` | `argument.resource.not_found`: the old query is gone |

With `advance_time` true, `tick step 20` moves `time query day` from 18100 to 18120. With it
false, the day stays.

Pumpkin differs:

- `time query day` answers `commands.time.query` with the day count, the meaning before 26.3;
- `time set day|noon|night|midnight` answers `commands.time.set.absolute`;
- `time query day repetition` is `command.unknown.argument`;
- the `tick step` answer carries the step as a String, where vanilla's is an Int.

## Sleep

- `ServerPlayer.startSleepInBed` checks the bed rule and for monsters, lies the player down,
  then calls `ServerLevel.updateSleepingPlayerList`. All of it runs while the server handles
  the `use_item_on`.
- `updateSleepingPlayerList` announces only when `SleepStatus.update` reports a change. The
  announcement is an overlay to every player in the level: `sleep.skipping_night` when enough
  sleep, else `sleep.players_sleeping` [sleeping, needed].
- `SleepStatus` counts players that are not spectators. Control counts too.
  `sleepersNeeded(pct) = max(1, ceil(active * pct / 100))`.
- `Player.tick` counts `sleepCounter` up to 100 while the player sleeps, and wakes it
  (`stopSleepInBed(false, true)`, which announces) when the bed rule says it can no longer
  sleep. Players tick while the world is frozen, so the 100 ticks of deep sleep pass on the
  wall clock.
- `ServerLevel.tick` checks, outside the `runsNormally` gate, whether enough players sleep and
  sleep deeply. If so, and `advance_time` is true, it moves the clock to `wake_up_from_sleep`
  (the next 0), then `wakeUpAllPlayers` with `stopSleepInBed(false, false)`: no announcement.
  The night skip therefore happens in a frozen world too.
- `ServerPlayer.stopSleepInBed` sends `animate` action 0 to the players tracking the sleeper
  and to the sleeper, then teleports it (`player_position`).

Live on vanilla, two players (Control left), a bed at 2..3 -60 0 facing east:

- At 18000 with `players_sleeping_percentage` 100, one player lies down. The sleeper gets
  `set_spawn` chat and `player_position` the first time; both players get the advancement chat
  the first time, the overlay `sleep.players_sleeping` [1, 2], and `set_entity_data` with pose
  2 (sleeping) and the bed. Six heartbeats later the day is still 18000.
- Still asleep, after `time set 23440` and single steps, the player wakes when the day reaches
  23478: `animate` 0, the overlay `sleep.players_sleeping` [0, 2], `player_position`, then pose
  0. In `time/sleep` Control is back for the step to dawn, so three players are online and the
  overlay reads [0, 3]. With the clock deopped for the step (`deop clock`), it hears no admin
  chat of Control's `tick step`; `op clock` afterwards sends it `commands.op.success` as admin
  chat (2026-10-16 play).
- At 18000 with 50, the overlay is `sleep.skipping_night`. About 5 s later, frozen, comes
  `set_time` with the overworld clock at 24000, `animate` 0, pose 0 and the sleeper's
  `player_position`, with no overlay. `time query day` answers 0 and
  `time query day repetition` 1.
