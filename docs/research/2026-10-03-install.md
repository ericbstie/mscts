# Install research — 2026-10-03

What `mscts adapter install` reads to find a server's latest build, name
it, and check that a file is for the Target (#156). **Verified** means
observed first-hand in this container; **source** means read in the
publisher's own files at the commit named.

## Which commit a Pumpkin nightly was built from

Two sources agree, and mscts reads both.

**The binary names its own commit.** **source, verified**
- `crates/pumpkin/build.rs` (at `4426d1113a211e6018a2db416e33b6b8a7802614`)
  runs `git rev-parse --short=7 HEAD` and `git rev-parse HEAD` and sets
  `GIT_HASH` and `GIT_HASH_FULL`; both are `unknown` when the build has
  no git checkout.
- `crates/pumpkin/src/command/commands/pumpkin.rs` formats them for the
  `/pumpkin` command as `"{} (Commit: {}/{}) - {} Contributors"`
  (`CARGO_PKG_VERSION`, `GIT_HASH`, the build profile), and
  `"Commit: {GIT_HASH_FULL}"` for its hover text.
- The compiler folds the constant part into one string. The nightly
  installed on 2026-10-02 (sha256 `b8382a8a…`, 126,447,960 bytes) holds
  `0.2.0+26.3-26.51 (Commit: 4426d11/` once, and the full
  `4426d1113a211e6018a2db416e33b6b8a7802614` once, right after a second
  `4426d11`. Read with `grep -a`. Earlier nightlies held `003d3c4` and
  `a4d6465` the same way (2026-09-26-pumpkin.md).
- `0.2.0+26.3-26.51` is the workspace `version` in `Cargo.toml`. The
  part after `+` names the Minecraft version, the Target's `26.3`.

**The `nightly` tag points at the commit the latest nightly was built
from.** **source, verified**
- `.github/workflows/nightly.yml` (same commit) runs daily at 03:00 UTC
  and only when `master` has moved past the tag. After every build has
  succeeded, its `draft_release` job runs
  `git tag --force nightly && git push --force origin tag nightly` on the
  built commit, then uploads the assets to the `nightly` release
  (`softprops/action-gh-release`), whose notes say
  `From commit: <short commit>`.
- The tag is lightweight: the ref advertisement of
  `https://github.com/Pumpkin-MC/Pumpkin.git/info/refs?service=git-upload-pack`
  (what `git ls-remote` reads) has
  `4426d1113a211e6018a2db416e33b6b8a7802614 refs/tags/nightly` and no
  peeled `^{}` line, while `refs/heads/master` was already
  `1859221e7ad1227f43277f74507f921c0acec83f`. Python's `urllib` (mscts's
  `https_get`) reads it here: about 190 KB.
- The tag moves before the assets are replaced, so for a few minutes a
  day the tag can name a newer commit than the binary. mscts uses the tag
  only to find the file. Whether the file is the build `pumpkin@<commit>`
  names, and which commit is recorded, the binary itself says
  (#158).

**Not reachable from this container** (403 from the agent proxy): the
REST API (`api.github.com/repos/Pumpkin-MC/Pumpkin/...`), the release
page HTML, `releases.atom` and `codeload.github.com`. The asset download
(`.../releases/download/nightly/pumpkin-X64-Linux`, a 302 to
`release-assets.githubusercontent.com`) and `raw.githubusercontent.com`
are reachable. **verified**

Pumpkin publishes only its latest nightly: the asset URL has no
version in it, and the release is replaced by each build. An older
commit can only be built from source.

The protocol a Pumpkin binary speaks is not in a form mscts can read
from the file. The Instance's readiness check refuses any other protocol
(a status ping must answer with the Target's).
